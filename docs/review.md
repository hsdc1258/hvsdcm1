## SVG 7종 좌표 판정

현재 데이터 실측 상한은 label 7자, item 14자, center 6자이며 1280px 4개 표본과 코드 계산에서는
즉시 드러나는 이탈을 찾지 못했다. 그러나 게이트가 허용하는 계약 상한(label 12, item 20,
center 14, items 0~4)까지 넣으면 아래 레이아웃은 성립하지 않는다.

| kind | 판정 | 좌표 근거 |
|---|---|---|
| `scale` | 현재·계약 상한 모두 대체로 안전 | 팬 높이가 item 수에 따라 증가하고 폭 315px가 item 20자(12px 기준 약 240px)를 수용한다. |
| `matrix2x2` | 현재·계약 상한 모두 대체로 안전 | 셀 364×190, 항목 기준선 26px 간격으로 4개까지 셀 안에 든다. |
| `flow` | **계약 상한 실패** | 박스 높이 92px인데 3~4번째 칩이 하단을 넘고, 12자 label은 x=108부터 약 192px를 차지해 x=248 칩과 겹친다. |
| `venn` | **계약 상한 실패** | 3열 범례 간격 245px에서 20자 item은 11.5px 기준 약 230px이고 x+26 오프셋 때문에 다음 열을 침범한다. |
| `timeline` | **계약 상한 실패** | 교대 배치 높이가 300px 고정이다. 위쪽 노드의 3~4번째 item은 축과 겹치며, 긴 항목은 인접 노드 칼럼도 침범한다. |
| `pyramid` | **계약 상한 실패** | 층 높이 96px에서 item 기준선이 y+60,+80,+100,+120이므로 3번째부터 다음 층으로 넘어간다. |
| `radial` | **계약 상한 실패** | 카드 높이 80px에서 3번째 item부터 이탈한다. 공백 없는 center 14자는 `wrapCenter()`가 접지 못해 지름 132px 원보다 넓다. |

`diagram.js`의 주석은 좌표 전제를 “실측 label 7 / items 14 / center 6”으로 적지만, 구조 게이트는
12 / 20 / 14를 허용한다. 따라서 현재 데이터에 대한 관찰과 스키마 계약의 안전성을 구분해야 한다.

## 회귀 확인

- 스크립트 로드 순서는 `smstudy/index.html:77-84`와 `scripts/validate.mjs:734-742`가 동일하고,
  `diagram.js`가 `app.js`보다 먼저 로드된다.
- 퀴즈 데이터 불변식(4 units / 13 subunits / 78 questions, 단원당 6)은 `npm test`로 통과했다.
- 이미지 폴백의 현재 구현 자체는 `naturalWidth`, load/error 양방향, hidden 기본값을 유지한다.
  다만 마크업–바인더 연결 회귀를 게이트가 못 잡는 문제는 B-4다.
- 인쇄용 light palette와 `@media print` 등록은 유지되며 신규 색 토큰은 없다.
- localStorage 키와 API app 이름 변경은 찾지 못했다.
- 정적 사이트 + ES module Worker 배포 모델을 바꾸는 변경은 찾지 못했다.

## 잘 된 점

- kind 집합은 `diagram.js` 레이아웃 함수와 `LAYOUTS` 등록부를 양방향 대조하며, 새 kind에 bounds가
  없으면 실패하도록 닫혀 있다. 하드코딩된 7종 목록만 순회하는 방식은 아니다.
- 아이콘 키 집합 자체는 `assets/vendor/lucide/icons.js`에서, 태그 사용 집합은 78문항에서 자동 도출한다.
- 태그 정합은 양방향이며 죽은 태그도 막는다.
- SVG는 색 리터럴 대신 CSS class/currentColor만 사용하고 새 커스텀 프로퍼티를 만들지 않았다.
- 좁은 화면 폴백은 container query를 우선 사용하고 media query를 안전망으로 두며 `hidden`으로
  SVG/목록 표시를 전환하지 않는다.
- 현재 데이터의 조사 헬퍼는 한글 종성 공식 `(code-0xac00)%28`을 올바르게 적용한다.
