무엇인가 — 사용량(/usage/index.html) 문서를 얼린 스냅샷이다. 링크된 CSS를 인라인하고 스크립트를 걷어냈다.
정적으로 반영한 상태 — 본문은 usage.js의 buildDashboard()를 실제로 실행해 얻은 마크업이다. 입력은 scripts/snapshot.mjs의 고정 표본(USAGE_FIXTURE)이고 기준 시각도 고정이라, 상대 시간이 흐르지 않는다.
여기서 확인할 것 — 상위 탭이 진행 중 · 중단됨 · 완료 셋이고 어느 것이 눌려 있는지 눈으로 갈리는지, 진행 중 패널 머리의 관제탑 | 조직도 모드 토글에서 기본값(관제탑)이 눌려 있는지, 관제탑 카드의 칩이 이름 · 역할 · 모델 · 상태 · 진행률 · 소요를 각자 슬롯으로 내고 위임 깊이가 들여쓰기로 남는지, (조직도 모드로 바꿔 보면) 총괄이 최상단 뿌리로 서고 수평 trunk에서 단계마다 개별 stem이 내려오는지, 카드가 되는 단계가 보고된 단계와 액터가 붙은 단계뿐이고 나머지(대기 · 기록 없음)는 조직도 아래 한 줄이 이름으로 받는지 (DESIGN.md §1.1 v9), 사용자 입력이 조직도 node로 만들어지지 않고 요청 원문이 상세 머리의 inset 한 곳에만 있는지, 노드 · 연결선 · 글자가 어디서도 겹치지 않는지, 오른쪽 Codex · Claude 한도 rail에서 제목과 수집 시각이 폭을 다투지 않는지, 게이지의 세 색 구간과 모르는 버킷 키(monthly)가 모두 실제 renderer 산출물에 있는지.
주의 — 미로그인 접근은 usage.js가 랜딩으로 되돌린다. 이 사본은 로그인한 방문자가 보는 화면이다. 조직도의 확대·이동 캔버스는 제거됐다: 트리는 일반 문서 흐름으로 원본 크기로 서고, 넘치면 조직도 상자만 가로로 스크롤한다. 그래서 이 사본에는 스냅샷 전용 CSS가 한 줄도 없다 — 배포되는 CSS 그대로이므로 사본에서 본 조판이 곧 실화면의 조판이다. 예전 사본은 캔버스 변환을 우회하는 전용 CSS 때문에 실제 초기 배율을 가렸고, 그것이 직전 리뷰가 지적한 사각지대였다.
기준 — 이 파일은 node scripts/snapshot.mjs가 만든 생성물이다. 손으로 고치지 않는다. npm run validate가 같은 생성기를 다시 돌려 이 파일과 대조하므로, 데이터·렌더러·CSS를 바꾸면 반드시 다시 만들어야 한다. 이 디렉터리는 밑줄로 시작하므로 GitHub Pages(Jekyll)가 게시하지 않는다 — 학습 내용이 들어 있어도 공개면에 오르지 않는다.
