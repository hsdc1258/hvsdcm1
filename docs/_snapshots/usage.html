무엇인가 — 사용량(/usage/index.html) 문서를 얼린 스냅샷이다. 링크된 CSS를 인라인하고 스크립트를 걷어냈다.
정적으로 반영한 상태 — 본문은 usage.js의 buildDashboard()를 실제로 실행해 얻은 마크업이다. 입력은 scripts/snapshot.mjs의 고정 표본(USAGE_FIXTURE)이고 기준 시각도 고정이라, 상대 시간이 흐르지 않는다.
여기서 확인할 것 — 진행 중/완료/전체 조직도 탭의 수치가 각각 2/1/3이고, 진행 중 병렬 task 중 선택된 한 panel만 보이는지, 선택된 세션의 조직도가 사용자 입력 → 총괄 → 입력/기획/구현/게이트/리뷰/수정/승인/완료 여덟 단계 전부로 뻗고 그 아래 실제 actor가 갈라지는지, 지나간 단계는 완료·앞으로 올 단계는 대기로 상태만 다른지, 노드·연결선·글자가 어디서도 겹치지 않는지, 오른쪽 Codex · Claude 한도 rail, 게이지의 세 색 구간, 모르는 버킷 키(monthly)가 모두 실제 renderer 산출물에 있는지.
주의 — 미로그인 접근은 usage.js가 랜딩으로 되돌린다. 이 사본은 로그인한 방문자가 보는 화면이다. 조직도는 실제 화면에서 휠 확대 · 끌어 이동하는 캔버스이고, 열리는 순간 트리 전체가 들어오도록 배율이 맞춰진다. 이 정적 사본은 스크립트가 없어 그 맞춤이 돌지 않으므로, 스냅샷 전용 규칙으로 캔버스 높이를 풀고 가로 스크롤을 허용했다 — 조직도 안을 옆으로 밀어 보면 실제 화면에서 끌어 이동했을 때와 같은 것이 보인다.
기준 — 이 파일은 node scripts/snapshot.mjs가 만든 생성물이다. 손으로 고치지 않는다. npm run validate가 같은 생성기를 다시 돌려 이 파일과 대조하므로, 데이터·렌더러·CSS를 바꾸면 반드시 다시 만들어야 한다. 이 디렉터리는 밑줄로 시작하므로 GitHub Pages(Jekyll)가 게시하지 않는다 — 학습 내용이 들어 있어도 공개면에 오르지 않는다.
