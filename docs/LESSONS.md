# LESSONS.md — 재발 방지 규칙

> 완료된 사이클의 리뷰 지적사항·오류를 명령문 규칙으로 축적한다. 사건 서술 대신
> "다음엔 이렇게 한다"만 쓴다. 각 규칙 끝의 (근거: …)는 실제 발생 사례를 가리킨다.

## 대비·토큰

1. 토큰의 명도를 바꾸거나 새 배경 위에 토큰을 쓸 때는 같은 계열의 다른 variant와
   alpha 합성 배경까지 전부 재계산해 대비표에 기록한다. 하나만 확인하고 나머지를
   유추하지 않는다.
   (근거: 사이클1 blocker-1→major-16 프린트 대비 저하, 사이클2 M-3 뱃지 4종 중
   2종 AA 미달, M-4 그라디언트 밝은 끝에서 본문 7:1 목표 미달)
2. 토큰에 "비활성 전용" 등 용도 제약 주석이 있으면, 새 규칙에 그 토큰을 쓰기 전에
   주석의 제약과 실제 배경 위 대비를 함께 확인한다.
   (근거: 사이클2 M-2 — `--text-4`(비활성 전용 주석)를 활성 섹션 라벨에 사용,
   surface 위 3.56:1로 AA 미달)
3. CSS 한 파일에 같은 셀렉터나 `:root`가 중복 선언돼 있으면, 값을 고칠 때
   특이도·순서를 따져 어느 블록이 실효 블록인지 확인하고 모든 블록을 함께 고친다.
   (근거: 사이클1 major-5→major-14, WordMaster `.primary-btn` 이중 블록 중
   후행 블록 수정 누락이 라운드를 넘겨 재발)

## 자동 검사(게이트)

4. 두 개의 독립된 존재 검사(`includes` 등)를 AND로 묶어 "요소 하나"를 검증한
   것처럼 쓰지 않는다. 단일 정규식/선택자로 검사 대상을 하나로 고정하고, 값을
   지우는 음성 테스트로 실제로 실패하는지 확인한다.
   (근거: 사이클2 M-6 — `drawerStudy` 존재와 `aria-hidden` 존재가 서로 다른
   요소를 봐도 통과)
5. 색 토큰·훅 이름 같은 검사 대상 목록을 하드코딩하지 않는다. 단일 원본
   (system.css의 `:root` 등)에서 파싱해 자동 도출하면 원본에 항목이 늘어도
   검사가 뒤처지지 않는다.
   (근거: 사이클2 M-7 — colorTokens 9개 하드코딩, system.css 25개 중 16개가
   검사 밖에 있었음)
6. 텍스트 검사(html/css/js grep)로 커버할 수 없는 자산(PNG 등 바이너리에 박힌
   글자)이 있으면 별도로 해시·mtime 잠금 검사를 둬 회귀를 막는다. "검사 통과 =
   요구사항 충족"이 아님을 전제한다.
   (근거: 사이클2 B-1 — `assets/og.png`가 구 브랜드 표기인 채 `npm test` 통과)
7. 검사 총 건수가 줄었다고 검사가 약해졌다고 판단하지 않는다. 목록형 검사를
   파싱 기반 전면 검사로 통합하면 건수는 줄어도 커버 범위는 넓어질 수 있다 —
   "이전엔 못 잡던 위반을 잡는가"를 재현 테스트로 판정한다.
   (근거: 사이클2 통합 라운드 — 5260→5256건으로 줄었지만 색 토큰 9종→73종
   자동 도출로 커버리지 확대)

## 프로세스

8. 문서 산출물(plan.md·review.md·LESSONS.md 등)은 완결 후 한 번에 커밋하지
   말고 작성 도중 자주 커밋한다. 백그라운드 에이전트는 프로세스 종료·API 한도로
   중단될 수 있고, 커밋 안 된 산출물은 통째로 유실된다.
   (근거: 사이클1 리뷰가 LESSONS.md 후보 규칙 3건을 제안했으나 커밋되지 않아
   사이클2 시작 시점에 이 파일 자체가 존재하지 않았음)
9. 새 UI 진입점을 추가할 때는 기존 동등 표면의 상태 규칙(로그인 게이팅 등)을
   함께 적용하거나, 다르게 할 경우 판단 근거를 plan.md에 남긴다. "동작이 안
   깨졌음"만으로는 완료 조건을 충족하지 못한다.
   (근거: 사이클2 M-1 — 상단바·푸터 링크에 게이팅 누락, 사후 D7로 "기존 동작
   보존" 판단을 남겨 정리)
10. 줄바꿈/공백 정규화(CRLF→LF 등)는 로직 변경과 별도 커밋으로 분리한다. 섞으면
    diff 통계(변경량 게이트 포함)가 실제 규모를 과장해 리뷰 비용이 커지고 게이트
    판정을 왜곡한다.
    (근거: 사이클2 N-9 — home.js 실 변경 +26/-2인데 diff는 +170/-146으로 표시)

## 자동 검사(게이트) — 사이클3 추가

11. 렌더 필수 필드나 DOM 훅을 소스 텍스트 정규식/포함 매칭으로 검사하지 않는다.
    렌더러를 실제로 실행해(예: 데이터 객체를 Proxy로 감싸 `get` 트랩으로 읽힌
    프로퍼티를 계측) 결과 마크업에 빈 슬롯(undefined/null/빈 문자열)이 있는지
    검사하고, 훅·선택자 검사는 실제 렌더 함수의 본문으로 범위를 좁힌다
    (`functionBody()` 등). 이렇게 하면 변수 별칭·구조분해·옵셔널 체이닝·함수
    밖 미사용 문자열 같은 "표현만 바꾼 우회"가 통과하지 못한다.
    (근거: 사이클3 라운드1 B-1~B-4 정규식 순회 우회 4건 → 라운드2 R2-B-1(별칭)·
    R2-B-3(함수 밖 문자열)로 같은 부류 재발 → 라운드3 런타임 수집·함수 경계
    한정으로 부류 자체를 닫음)
12. 하나의 데이터가 화면 폭에 따라 서로 다른 렌더 경로(넓은 화면 SVG 캔버스 /
    좁은 화면 폴백 목록 등)로 그려지면, 검사도 kind·경로별로 전부 계측한다.
    한쪽 경로의 개수만 세고 통과시키지 않는다.
    (근거: 사이클3 R2-B-2 — 넓은 화면 flow 아이콘 렌더 한 줄을 지워도 좁은
    화면 폴백 카운트만 보는 검사가 통과)
13. 스크린샷 대체용 스냅샷 문서는 손으로 얼리지 말고, 현재 소스에서 다시 만들어
    커밋된 파일과 바이트 대조하는 생성 스크립트로 관리한다. 소스가 바뀌면
    스냅샷이 자동으로 낡아 게이트가 실패해야 한다.
    (근거: 사이클3 R2-M-1 — 손으로 고정한 스냅샷의 키워드를 바꿔도 게이트 통과
    → 라운드3 `scripts/snapshot.mjs` 재생성+바이트 대조로 해소)
14. DOM 크기 계측(`getBBox()` 등)으로 "겹침 0 / 이탈 0"을 주장하기 전에, 계측
    대상이 실제로 보이는 상태인지 자체를 함께 잰다(표시 요소의 폭이 0인 케이스
    수 등). 헤드리스·좁은 뷰포트 환경은 CSS 폴백(컨테이너 쿼리 등)을 트리거해
    대상이 `display:none`이 될 수 있고, 그 상태의 크기 측정은 전부 0이라
    "위반 0건"이 공허하게 참일 수 있다.
    (근거: 사이클3 — `innerWidth=0`에서 컨테이너 쿼리가 폴백으로 넘어가 SVG가
    `display:none`, `getBBox()` 288개 전수 0으로 "겹침 0"이 무효였음)
15. 문자 길이 같은 콘텐츠 상한을 게이트(스키마)에 선언할 때는, 그 상한이 실제로
    그리는 좌표·레이아웃이 수용 가능한 값인지 좌표 산식으로 직접 검산하고
    게이트 상한과 좌표가 전제한 값을 반드시 일치시킨다(다르면 더 낮은 쪽으로
    통일). "현재 데이터가 상한 안에서 안전해 보인다"만으로 상한을 확정하지 않는다.
    (근거: 사이클3 M-2 — 게이트 허용 12/20/14자, 좌표 코드 주석의 전제는 실측
    7/14/6자로 서로 달라 flow·venn·timeline·pyramid·radial 5종이 계약 상한에서
    겹치거나 이탈)
16. 함수 경계·필드 존재 등을 소스 텍스트로 판정하는 정규식은 CRLF(`\r`)를
    흡수하거나 매칭 전에 줄바꿈을 정규화한다. `core.autocrlf=true`인 Windows
    체크아웃에서는 커밋 시 LF였던 파일도 워킹 트리에서 CRLF로 바뀌어, 로직이
    멀쩡한 정상 소스가 거짓 실패할 수 있다.
    (근거: 사이클3 R3-M-1 — `functionBody()`의 LF 전용 함수 끝 정규식이
    `autocrlf=true` 체크아웃에서 정상 HEAD를 7건 실패시킴)

## 콘텐츠 정확성

17. 개념 설명 문구를 작성·수정할 때는 근거 문항의 정답 선지뿐 아니라 **오답
    선지가 부정하는 진술 내용**까지 확인한다. 오답 선지가 틀렸다고 지목한
    진술을 그대로 정답 개념 설명으로 옮겨 적지 않는다.
    (근거: 사이클3 M-4 — "절대적 빈곤 기준선은 시공간을 넘어 보편"이라는,
    기출 문항이 오답으로 지목한 진술을 정답 개념 설명에 그대로 씀)
18. 같은 파일 안에 개념을 설명하는 서술문과 비교표(대조표)가 함께 있으면, 커밋
    전에 두 표현이 같은 판정을 내리는지 맞춰 본다. 서술문만 고치고 표는
    그대로 두거나 그 반대인 채로 남기지 않는다.
    (근거: 사이클3 R2-M-3 — 서술문은 계층 대물림을 "세대 간 수평 이동"으로,
    같은 파일의 비교표는 올바르게 "이동 없음/대물림"으로 적어 내부 모순)

## 프로세스 — 사이클3 추가

19. 병렬 세션이 동시에 작업 중일 수 있는 저장소에서는 `git add -A`·`git add .`를
    쓰지 않는다. 이번 커밋이 실제로 건드린 파일만 경로로 지정해 스테이징한다.
    (근거: 사이클3 D-4 — 3b 커밋이 `git add -A`로 다른 세션의 미커밋 파일을
    함께 담아 커밋 경계가 섞임)
20. 컨텍스트가 넘칠 만큼 큰 단일 기능(콘텐츠 전면 재작성 + 렌더러 + 게이트 등)은
    **같은 모델이 하위 단계를 순차로 이어받는 방식**으로 나눠도 된다. "레이어
    분할 금지"는 *서로 다른 모델*이 한 기능의 레이어를 나눠 갖는 것을 막는
    규칙이며, 같은 모델의 순차 핸드오프까지 막지 않는다. 핸드오프는 채팅이
    아니라 커밋과 plan.md 같은 문서로 한다.
    (근거: 사이클3 §10 — 3단계를 3a(데이터)/3b(렌더러)로 opus 5가 순차 처리,
    핸드오프를 plan.md에 기록해 정상 작동)

## 승격 제안

아래 두 규칙 계열은 이번까지 3회 이상 반복돼 CLAUDE.md "승격된 규칙" 섹션
편입을 제안한다 (이 파일에서는 제안만 하며 CLAUDE.md는 직접 수정하지 않음).

- **토큰 대비 전수 검산** (규칙 1~2) — 사이클1 1회(blocker-1→major-16) +
  사이클2 2회(M-3, M-4) = 총 3회. 사이클3에는 신규 색 토큰이 0개라 해당
  계열의 새 사례는 없었다(집계 갱신 없음).
- **자동 게이트 사각지대 점검** (규칙 4~6, 11~14) — 사이클1 1회(blocker-2, 선행
  사례) + 사이클2 3회(M-6, M-7, B-1) + **사이클3 8회**(라운드1 B-1~B-4,
  라운드2 R2-B-1~B-3·R2-M-1) = 누적 **12회**. CLAUDE.md에 이미 "승격된 규칙"
  으로 한 차례 올라간 뒤에도 같은 사이클 안에서 세 라운드에 걸쳐 반복
  재발했다(정규식 순회 우회 → 별칭·함수 밖 문자열로 표현만 바꿔 재우회 →
  런타임 실행·함수 경계 한정으로 부류를 닫고서야 종결). **문서 승격만으로는
  재발을 막지 못했다는 뜻이므로, 다음 사이클부터는 "검사 설계 원칙"이 아니라
  "판정 근거를 실행 결과로 옮긴다"는 구체적 방법(규칙 11)까지 CLAUDE.md에
  명시하는 것을 제안한다.**
