# LESSONS.md — 재발 방지 규칙

> 완료 사이클의 지적사항을 명령문 규칙으로 축적한다. 사건 서술 대신 "다음엔
> 이렇게 한다"만 쓴다. (근거: …)는 실제 발생 사례.

## 대비·토큰

1. 토큰 명도 변경·새 배경 사용 시 같은 계열·alpha 합성 배경까지 전부 재계산해
   대비표에 기록하고, 게이트가 주석 수치를 :root 실값과 자동 대조하게 한다.
   부모 표면마다 흔들리는 알파 상태색은 불투명 토큰으로 구워 고정한다. 용도
   제약 주석(비활성 전용 등)이 붙은 토큰은 쓰기 전 제약·실제 대비를 함께
   확인한다. (근거: 사이클1 1회+2 3회+4 2회(M-9 표 9곳 불일치, M-10 알파
   hover 3.94:1 미달)=6회, CLAUDE.md 승격됨)
2. CSS 한 파일에 같은 셀렉터/`:root` 중복 선언이 있으면 실효 블록을 특이도·
   순서로 확인하고 모두 함께 고친다. (근거: 사이클1 major-5→14)

## 자동 검사(게이트)

3. 독립된 존재 검사 두 개를 AND로 묶어 "요소 하나" 검증처럼 쓰지 않는다.
   교차 매핑(A↔B) 검사는 집합 포함이 아니라 키별 정확한 대응으로 비교한다.
   (근거: 사이클2 M-6 + 사이클4 M-5 이모지 맞바꿔도 통과=2회)
4. 검사 대상 목록·배포 판정 전제("이 경로는 배포면 아님" 등)를 하드코딩하지
   않고 단일 원본(설정·배포 규칙·소스)에서 자동 도출한다. (근거: 사이클2 M-7
   색토큰 9개 + 사이클4 B-1 배포면 전제·M-1 화면 목록 하드코딩=3회, 승격 후보)
5. 텍스트 grep 사각지대(바이너리 등)는 해시·mtime 잠금으로 회귀를 막는다.
   (근거: 사이클2 B-1) 검사 총 건수 감소를 약화로 보지 않는다 — 재현 테스트로
   커버 범위를 판정한다. (근거: 사이클2 통합 라운드)
6. 함수 경계·필드 존재는 소스 정규식 대신 실제 실행 결과(런타임 계측)로
   판정한다. 정규식으로 HTML을 줄 단위로 자를 때는 같은 태그 첫 닫힘에서
   멈추지 말고 중첩 깊이를 추적한다 — 별칭·구조분해·중첩 태그로 표현만 바꾼
   우회를 막는다. (근거: 1+2+3(8회)+4 M-6 중첩 div 뒤 누락, 누적 12회+,
   CLAUDE.md 승격됨)
7. 화면 폭별 다른 렌더 경로(SVG/폴백)는 경로별로 전부 계측한다. (근거: 3
   R2-B-2) 콘텐츠 상한 선언 시 좌표 산식의 전제값과 일치시킨다. (근거: 3 M-2)
8. 스크린샷 대체 스냅샷은 소스에서 재생성해 바이트 대조하고, 화면별 실제
   쓰는 CSS만 인라인한다(공용 세트 재사용 시 화면 고유 스타일 누락). (근거:
   3 R2-M-1 + 4 — WordMaster 스냅샷에 `.wm-*` 누락, `6521527`로 분리)
9. DOM 크기 계측(getBBox 등)으로 "겹침·이탈 0"을 주장하기 전 대상이 실제
   보이는 상태인지 함께 잰다. (근거: 3 — 컨테이너 쿼리 폴백으로 전수 0)
   소스 텍스트 정규식은 CRLF를 흡수/정규화한다. (근거: 3 R3-M-1)
10. 마크업에 반복 노출되는 식별 값(이모지 등)을 리터럴로 쓰지 않는다. 단일
    데이터 맵(대상→값)에서 키로 공급해 한 곳만 고치면 되게 한다. (근거: 4
    M-4 — index.html 이모지 7개 여러 위치 하드코딩)

## 콘텐츠·접근성·헌장

11. 개념 설명 작성 시 오답 선지가 부정하는 진술까지 확인한다 — 오답이 틀렸다고
    지목한 문장을 정답 설명에 옮기지 않는다. 서술문·비교표가 함께 있으면 커밋
    전 판정 일치를 맞춘다. (근거: 3 M-4, R2-M-3)
12. 시각 스타일만 바꿀 목적으로 시맨틱 요소(h2 등)를 비시맨틱(p 등)으로
    바꾸지 않는다 — CSS로 겉모습만 바꾸고 위계·`aria-labelledby`는 유지한다.
    (근거: 4 M-3 rangeHead 등 3개 라벨 h2→p로 제목 탐색점 소실)
13. 시스템 프리미티브가 있는 UI(셀렉트 화살표 등)를 하위 앱에서 재구현하지
    않는다 — 금지 효과(그라디언트 등)가 재유입되기 쉽다. 코드 주석만으로
    헌장 예외를 만들지 않고 DESIGN.md를 먼저 개정한다. (근거: 4 M-7 중복
    구현, M-8 "floating overlay exception" 임의 예외)

## 프로세스

14. 문서 산출물은 완결 후 한 번에 커밋하지 말고 도중 자주 커밋한다. (근거: 1
    — 미커밋 후보가 사이클2 시작 시 유실)
15. 새 UI 진입점은 기존 동등 표면의 상태 규칙(로그인 게이팅 등)을 함께
    적용하거나 근거를 plan.md에 남긴다. (근거: 2 M-1)
16. 줄바꿈/공백 정규화는 로직 변경과 별도 커밋으로 분리한다. (근거: 2 N-9)
17. 병렬 세션 저장소에서 `git add -A`/`.`를 쓰지 않고 건드린 파일만 스테이징
    한다. (근거: 3 D-4)
18. 같은 모델의 순차 핸드오프(3a→3b 등)는 레이어 분할 금지 위반이 아니다 —
    핸드오프를 커밋·plan.md로 남긴다. (근거: 3 §10)
19. 완료 조건에 정량 개선(밀도·성능 등)이 걸리면 기준 커밋과 현재를 같은
    뷰포트·상태에서 실측해 수치·증감률·재현 명령을 남긴다. (근거: 4 M-2 —
    밀도 개선 수치 증거 부재 → 320/768/1280 실측표+재현 명령으로 해소)
