# 사이클4 전면 재설계로 넘기는 인계 사항

> 헌장 적용 트랙(`c05ae71`~`bac9b58`)의 결과물 중 **재설계가 물려받아야 할 것**만 적는다.
> 이 트랙은 여기서 종료하며, 화면 CSS·마크업의 소유권은 사이클4 재설계에 넘긴다.

## 1. 버려도 되는 것 (방어하지 않는다)

`smstudy` 개념 노트의 참고서 조판, 카드 스택 정리, 학습 기록 섹션 구획 등 **화면 단위 조판**은
전면 재설계가 다시 그릴 대상이다. 되살리려 애쓰지 말고 새 설계대로 덮어써라.
`plan.md:25`대로 `DESIGN.md` 자체가 개정되면 이 트랙이 적용한 것은 정의상 구버전 계약이다.

## 2. 팔레트를 새로 짜도 유지돼야 하는 정책 3가지

- **blur / glass 금지에 예외를 만들지 마라.** 이번 트랙에서 감사 문서가 "장식면 한정"이라는
  헌장에 없는 예외를 스스로 만들어 `backdrop-filter`를 존치시켰고, 리뷰어 두 명이 독립적으로
  같은 지적을 했다(major). 결국 5곳 전부 제거하고 불투명 표면색으로 갔다.
  **예외가 필요하면 헌장을 먼저 고치고 나서 코드를 고쳐라.** 순서가 반대면 감사가 무력해진다.
- **시각 통합이 의미 구조를 지우지 않게 하라.** 카드 개수를 줄이려고 독립 `section`과 제목을
  익명 `div`/`strong`으로 바꾸자 heading/region과 스크린리더 탐색점이 사라졌다(major).
  카드 통합과 `section` + 제목(`aria-labelledby`) 유지는 양립한다. 제목 위계는 건너뛰지 않는다.
- **선택자 범위를 좁힐 때 그 클래스의 다른 사용처를 먼저 세라.** `.sm-section`을 특정 부모의
  직계 자식으로 좁히면서 같은 클래스를 쓰던 학습 기록 화면이 간격과 구분선을 함께 잃었다(major).
  감사 문서에는 "그 화면은 건드리지 않았다"고 적혀 있었다 — 의도와 실제가 달랐다.

## 3. 대비 검산은 반올림까지 맞춰라

`--text-2` on `--bg-alt`를 7.65:1로 적었으나 실제 계산값은 7.6448:1이라 7.64:1이 맞았고,
이것 하나로 재검토에서 major가 났다(`f9d26bb`). 승격 규칙 "토큰 대비 전수 검산"은
**주석과 실제 값이 어긋나지 않을 것**을 요구하므로 소수 둘째 자리까지 실제로 계산해라.

**새 팔레트를 짜면 현재 `system.css`의 대비표와 `docs/design-audit.md`의 수치는 전부 무효가 된다.**
토큰 값을 바꾸는 순간 표 전체를 다시 계산해야 하며, 옛 수치를 남겨 두면 그 자체가 결함이다.

## 4. 병렬 작업에 대한 결론

이번 사이클에 같은 브랜치·같은 작업 트리에 실행자 둘이 동시에 붙어 사고가 두 번 났다.
`git commit -a` 성격의 커밋이 남의 미완성 변경을 자기 커밋에 쓸어담았고(`3f962bd`),
`docs/review.md` 경로가 충돌해 한쪽 리뷰 문서가 덮어써졌다.

- 한 저장소에는 **실행자 하나만** 붙인다. 이 트랙이 손을 떼는 것으로 그 조건을 만족시킨다.
- 불가피하게 병렬이면 `git worktree`로 폴더를 분리하고, 산출물 파일명을 트랙별로 나눈다.
- 어느 경우든 `git add -A` / `git commit -a`를 쓰지 않는다. 고친 파일만 경로로 명시해 add한다.
