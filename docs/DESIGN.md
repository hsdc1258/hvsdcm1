# 디자인 헌장 (DESIGN.md)

> **이 문서는 hvsdcm1 프론트엔드의 시각 품질 계약이다.** 기획·구현·리뷰 모든 단계가
> 이 문서를 준수해야 하며, 위반은 리뷰에서 major 이상으로 다룬다.
>
> 배경: 2026-08-26 외부 피드백(디시 AI활용 갤러리)에서 전형적인 AI 슬롭 패턴이
> 확인됐다 — 단락 전체의 디스플레이급 조판, 장식 프리미티브 남발, 강조색 미수렴,
> 어절 쪼개짐. 개별 결함의 공통 원인은 "규칙 부재"였다. 기계 게이트는 틀림만 잡고
> 좋음은 못 재므로, 취향은 이 문서로 **입력에서 고정**한다.

## 1. 레퍼런스 우선 원칙

새 화면(뷰)을 만들거나 재조판할 때, **기획 단계에서 화면 유형별 레퍼런스를 먼저
명시**하고 그 레이아웃 어법 밖의 패턴은 쓰지 않는다.

| 화면 유형 | 레퍼런스 | 어법 |
|---|---|---|
| 랜딩 (index.html) | apple.com 제품 페이지 | 큰 여백, 짧은 헤드라인, 절제된 강조 |
| 학습·개념 화면 (smstudy 개념 노트, WordMaster 학습) | **문제집·참고서 조판** | 높은 밀도, 조용한 위계, 훑기 좋은 리스트 |
| 조작 화면 (시험 진행, 학습 기록, admin) | 데스크톱 앱 (Apple HIG) | 툴바·사이드바·표·시트 |

- 학습 화면에 마케팅 패턴(히어로 콜아웃, 통계 쇼케이스, 대형 카피)을 넣지 않는다.
- 레퍼런스를 벗어나는 새 패턴이 필요하면 plan.md에 근거를 적고 나서 쓴다.

## 2. 타이포그래피 위계

- **디스플레이·타이틀급(`--fs-display*`, `--fs-title-1`)은 30자 이하 헤드라인 전용.**
  마침표가 있는 문장, 두 문장 이상의 텍스트는 본문 크기(`--fs-body*`)로 조판한다.
  "타이틀 폰트에 단락 양"이 이 헌장이 막는 제1 결함이다.
- 글 양과 글자 크기는 반비례한다. 강조하고 싶은 긴 문장은 크기가 아니라
  배치(여백, 구분선, 배경면)로 강조한다.
- **한국어 텍스트 컨테이너에 `word-break: keep-all` 필수** (`overflow-wrap: break-word`
  병용). 어절 중간이 쪼개지는 조판을 금지한다.
- 억지 줄바꿈(`<br>`, 공백 조절)으로 조판을 교정하지 않는다. 줄바꿈이 어색하면
  크기 배정이 틀린 것이므로 크기를 내린다.

## 3. 색

- **강조색은 화면(뷰)당 1색.** 기본 강조는 `--accent` 하나로 수렴시킨다.
- 상태색(`--green*`, `--red*`, `--orange*`)은 상태 표시(성공·오답·경고)에만 쓴다.
  장식·구획 목적으로 상태색을 쓰지 않는다.
- **금지: 그라디언트 장식, 유리 효과(blur/glass), 무지개·다색 보더, 보라색 배경면.**
  그라디언트는 동일 색상 계열의 미묘한 표면 깊이(예: `--surface`→`--bg`)에만 허용.
- 색 토큰은 `assets/css/system.css`가 단일 원본이다 (기존 규칙 유지).

## 4. 장식 상한

- 한 뷰에 다음 장식 프리미티브 중 **2종 이하만** 쓴다:
  번호 뱃지(동그라미 숫자) / 프로그레스 바 / 통계 타일(대형 숫자) / 색 배너.
- 프로그레스 바는 **실제 진행 데이터**(사용자의 진행률·정답률)에만 쓴다.
  정적 콘텐츠의 비중 표현에 쓰지 않는다.
- 리스트의 기본값은 **일반 리스트**다. 번호 뱃지·아이콘 리스트는 순서 자체가
  학습 내용일 때만 쓴다.
- 카드는 정보의 경계가 필요할 때만 쓴다. **카드 3연속 스택이 나오면 설계를 의심하라** —
  대개 표, 리스트, 또는 구분선으로 충분하다.
- 기본값은 가장 단순한 형태다. 살은 필요가 증명될 때 붙인다.

## 5. 카피 (문구)

- 화면에 넣는 문장은 짧게. 본문 한 문장 60자 이하, 헤드라인 30자 이하
  (사이클3 plan R1과 동일).
- **구현 완료 전 오타·어색한 줄바꿈 교정 패스를 1회 수행**하고, 리뷰는 화면의
  실제 렌더 텍스트를 읽으며 교정 여부를 확인한다.

## 6. 검증 — 수치가 못 재는 것

- 기계 게이트(대비·토큰·변경량·a11y)는 "틀리지 않음"만 보증한다.
- **시각 품질은 스크린샷으로 확인한다**: 구현자와 리뷰어는 완성 화면의 스크린샷을
  레퍼런스(§1)와 나란히 놓고 대조한다. computed style 수치 확인은 시각 확인의
  보조 수단이지 대체 수단이 아니다.
- 스크린샷 확보가 환경상 불가능하면 그 사실을 산출물에 명시하고, 시각 확인이
  미완료임을 완료 보고에 포함한다 (조용히 생략 금지).

## 7. 리뷰 체크리스트 (요약)

리뷰어는 아래를 기계적으로 훑는다:

- [ ] 화면별 레퍼런스가 plan에 명시됐고 결과물이 그 어법 안에 있는가
- [ ] 디스플레이급 크기에 문장·단락이 조판된 곳이 없는가
- [ ] `keep-all` 누락·어절 쪼개짐·억지 줄바꿈이 없는가
- [ ] 한 뷰의 강조색이 1색으로 수렴하는가
- [ ] 장식 프리미티브가 뷰당 2종 이하인가, 카드 3연속 스택이 없는가
- [ ] 오타·어색한 문구가 렌더 화면에 없는가
- [ ] 스크린샷 대조를 실제로 수행했는가 (미수행 시 보고에 명시됐는가)
