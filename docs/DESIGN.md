> **이 문서는 hvsdcm1 프론트엔드의 시각 품질 계약이다.** 기획·구현·리뷰 모든 단계가
> 이 문서를 준수해야 하며, 위반은 리뷰에서 major 이상으로 다룬다.
>
> 개정 이력
> - v1 (2026-08-26) 외부 피드백에서 확인된 AI 슬롭 패턴(단락의 디스플레이급 조판,
>   장식 프리미티브 남발, 강조색 미수렴, 어절 쪼개짐)을 막기 위해 제정.
> - **v2 (2026-08-26, 사이클4)** 사용자가 완성본을 보고 "못봐주겠다, 갈아엎어라"고
>   판정했다. 레퍼런스를 "문제집 조판"에서 **애플 시스템 UI**로 옮기고, 이모지 체계와
>   밀도 규칙을 신설했다. 근거는 `docs/plan.md` §2.
> - **v3 (2026-08-27, 사이클5)** 운영 화면(admin·usage)의 레퍼런스를 "macOS 앱"에서
>   **클라우드 콘솔 대시보드**로 구체화했다(§1.1). 사용자가 보낸 참고 스크린샷의 문법을
>   워크스페이스 `docs/plan.md` §3.4가 서술로 옮겼고, 이 문서는 그 요지를 계약으로 편입한다.
> - **v4 (2026-08-27)** 공식 로고 확정 — §8 신설. 사용자가 기하 H 심볼을 메인 로고로
>   확정하고 규칙 승격을 지시했다.
> - **v5 (2026-08-27)** 확정 로고를 실제 화면에 적용했다. 랜딩 상단바·드로어·푸터
>   3곳에 `.brand-mark`를 삽입했고, admin 사이드바의 이모지 4종(🧭🧑💻📋)을 걷어내고
>   최상단 흰 헤어라인 엠블럼(`.sidebar-emblem`)으로 대체했다 — §5.1 표에서 해당 4행을
>   지운다.
> - **v6 (2026-08-27)** usage를 Codex 한도와 실제 AI 하네스 상태가 한 화면에서 만나는
>   운영실로 확장했다. Main Codex → 현재 gate → 실행자/검토자/WebGPT → 검증 artifact의
>   관료형 계층과 모바일 직렬화 규칙을 §1.1에 추가했다.
> - **v7 (2026-08-27)** 병렬 세션을 세로 카드 목록이 아닌 세션 탭으로 선택하고,
>   gate를 조직 구성원처럼 그리던 구조를 폐기했다. 선택된 세션은 Main Codex에서 실제
>   actor들로 가지가 갈라지는 보고 조직도로 표시하며 gate와 artifact는 메타 정보로 분리한다.
> - **v8 (2026-08-27)** usage를 실제 하네스 계약에 맞춘 command center로 재조판했다.
>   중복 요약 스트립을 제거하고 선택 세션의 4단계 흐름과 실제 actor 조직을 본문에, 실제
>   Codex 사용 한도만 sticky 우측 rail에 둔다. Apple HIG의 명확한 위계, GitHub Primer의
>   tab-panel 근접성, IBM Carbon의 key line·비대칭 정보 위계 원칙을 적용한다.

## 0. 이 헌장이 막는 두 가지 실패

1. **슬롭** — 규칙 없이 장식을 쌓아 올린 화면. v1이 막던 실패다.
2. **밋밋함** — 겁먹고 덜어내기만 한 화면. v2가 추가로 막는 실패다.

직전 사이클에서 나는 "아이콘은 의미를 더할 때만"이라며 아이콘을 41개에서 2개로 줄였고,
사용자는 그 결과를 보고 밋밋하다고 했다. **덜어내는 것 자체가 좋은 디자인이 아니다.**
좋은 디자인은 *일관된 체계* 안에서 필요한 만큼 쓰는 것이다. 아이콘·이모지를 줄이는 것이
목적이 되어서는 안 되며, 줄일 때의 판단 기준은 "체계에 속하는가"이지 "개수가 적은가"가
아니다.

## 1. 레퍼런스 우선 원칙

새 화면(뷰)을 만들거나 재조판할 때, **기획 단계에서 화면 유형별 레퍼런스를 먼저
명시**하고 그 레이아웃 어법 밖의 패턴은 쓰지 않는다.

| 화면 유형 | 레퍼런스 | 어법 |
|---|---|---|
| 랜딩 (`index.html`) | **apple.com 다크 제품 페이지** | 큰 여백, 짧은 헤드라인, 절제된 강조, 스크롤 리듬 |
| 학습 (smstudy 개념 · WordMaster) | **iOS 설정·건강 앱의 그룹 리스트 + 인셋 카드** | 높은 밀도, 둥근 그룹 컨테이너, 행 단위 위계 |
| 조작 (시험 진행 · 학습 기록) | **macOS 앱 (Apple HIG)** | 툴바·사이드바·표·시트 |
| 운영 (`admin` · `usage`) | **클라우드 콘솔 대시보드** (§1.1) | 그룹형 사이드바, 카테고리별 뷰, 요약 스트립, 라벨/값 위계 |

- 학습 화면에 마케팅 패턴(히어로 콜아웃, 통계 쇼케이스, 대형 카피)을 넣지 않는다.
- 랜딩 화면에 학습 화면의 밀도(그룹 리스트 연속)를 그대로 옮기지 않는다. 반대도 같다.
- **랜딩은 로그인 여부와 무관하게 본문에서 학습을 말하지 않는다.** 학습·사용량 진입은
  좌상단 드로어 하나로 모은다. 이는 취향이 아니라 제품 결정이다(워크스페이스
  `docs/plan.md` §1). 게이트는 `scripts/validate.mjs`의 `validateLandingGating()`이다.
- 레퍼런스를 벗어나는 새 패턴이 필요하면 `plan.md`에 근거를 적고 나서 쓴다.

### 1.1 운영 화면 문법 — 콘솔 대시보드

레퍼런스는 클라우드 호스팅 콘솔의 서버 상세 화면이다. **admin과 usage는 같은 문법을
쓴다** — 두 화면이 서로 다르게 보이면 "한 벌"이라는 인상이 거기서 깨진다.

- **캔버스** — 순검정 배경 위 한 단 밝은 다크 패널, 1px 헤어라인 경계. 그라디언트·글로우
  없음(§3·§4와 동일하다. 이 레퍼런스는 색 규칙과 충돌하지 않는다).
- **사이드바** — 항목을 **대문자 소제목 라벨(`.sidebar-label`)로 묶은 그룹**으로 낸다.
  **각 항목은 작은 아이콘 + 텍스트**(`.sidebar-item` 안에 `.emoji` 슬롯 + `.sidebar-item-text`)이고,
  활성 항목은 어두운 필 배경(`.sidebar-item[aria-current]`)으로 구분한다.
  아이콘 글리프는 마크업에 적지 않는다 — `data-emoji` 슬롯을 §5의 매핑이 채운다.
- **한 화면 한 주제** — 카테고리를 고르면 그 뷰만 렌더한다. 여러 섹션을 세로로 이어
  붙이지 않는다. 숨김은 CSS 클래스가 아니라 `hidden`으로 하고, 뷰 컨테이너의 기본
  `display`는 `none`이어야 한다(저자 규칙이 UA의 `[hidden]`을 이기기 때문).
- **콘텐츠 헤더** — 좌측에 대상 이름(`.view-head` h1 + 부제), 우측에 소형 액션 버튼
  나열(`.btn-sm`). 뷰가 바뀌어도 헤더의 자리는 그대로다.
- **상태 요약 스트립** — admin처럼 서로 다른 운영 지표를 비교하는 뷰는 상단의 가로
  1카드 N칸(`.summary-strip`)을 쓴다. usage는 세션 탭·현재 gate·한도 위젯에 같은 값이
  이미 있으므로 요약 스트립을 쓰지 않는다. 중복 수치를 한 번 더 카드화하지 않는다.
- **지표** — 시계열 데이터가 없으므로 차트는 만들지 않는다. 비율은 퍼센트 게이지
  (`.gauge-track` / `.gauge-fill`)로 내고, 게이지는 **실제 진행·소진 데이터에만** 쓴다(§6).
- **밀도** — 높게 하되 그룹화로 정리한다. 설명 문장을 타일마다 붙이지 않는다.
- **병렬 세션 탭** — 동시에 보고된 task를 세로로 전부 펼치지 않는다. 상태·진행률·분류가
  보이는 `tablist`에서 세션을 하나 선택하고 대응하는 `tabpanel` 하나만 표시한다. 클릭뿐 아니라
  좌우 방향키·Home·End로 전환할 수 있어야 하며, 모바일은 탭 스트립만 가로 스크롤한다.
- **하네스 조직도** — 장식 피라미드나 큰 카드의 세로 적층이 아니라 실제 actor의
  `parent_id` 보고 계층을 그린다. Main Codex(기획·통합·최종 판정)를 최상단에 두고,
  투입된 실행자·검토자·WebGPT를 고전적인 중앙 trunk·수평 branch·개별 stem으로 연결한다.
  gate와 artifact는 사람이 아니므로 조직도 node로 만들지 않고 선택 세션의 메타 정보로
  분리한다. WebGPT도 별도 서비스 배너가 아니라 모델을 가진 actor로 표시하고, 미투입
  실행자를 가짜로 만들지 않는다. 모바일에서는 같은 부모-자식 관계를 세로 트리로 직렬화한다.
- **usage split view** — 데스크톱은 선택 세션 본문과 실제 Codex 한도 rail을 `main + aside`
  2열로 둔다. rail은 세션 요약이나 가짜 KPI를 넣지 않고 계정 한도·초기화·수집 시각만
  담는다. 1100px 아래에서는 한 열로 돌아가며 page-level 가로 스크롤을 만들지 않는다.
- **실제 pipeline** — 단계는 제어면과 report schema가 함께 보장하는
  `구상 -> 작업 -> 검토 -> 완료`만 쓴다. 사용자 입력, 배포 모델, 검토자 같은 노드를
  추측해 추가하지 않는다. actor의 모델·역할·현재 작업은 report 값을 라벨과 함께 그대로
  표시하고, 미보고 actor는 만들지 않는다.
- **작업 카테고리** — Discord에서 들어온 안정적인 분류 키를 기준으로 프로젝트,
  pipeline 개선 프로토콜, 파이프라인 시각화 같은 작업 묶음을 별도 섹션으로 나눈다.
  모델명과 추론 단계는 합쳐 추측하지 않고 각각 수집한 뒤 카드에는 `모델 · 추론 단계`로
  함께 표시한다. 분류가 없는 과거 payload만 `기타 Codex 작업`으로 호환한다.

**적용 제외와 사유** — 레퍼런스에 있으나 이 사이트가 **의도적으로 채택하지 않은** 요소다.
헌장은 구현의 사후 기술이 아니라 입력이므로, 빼는 것도 근거와 함께 여기 적는다(§1 마지막 줄).

| 요소 | 판정 | 사유 |
|---|---|---|
| 사이드바 상단의 **서비스 레벨 메뉴** (대시보드/서버/네트워크/청구…) | 적용 제외 | 콘솔의 그 메뉴는 **서비스가 여럿일 때** 서비스를 갈아타는 장치다. 이 사이트의 운영 화면은 `admin`·`usage` 둘뿐이고, 화면 사이 이동은 상단바(`/` 홈)와 드로어 하나로 모은다는 제품 결정이 이미 있다(§1 · plan.md §1-1). 운영 화면이 셋 이상으로 늘면 이 줄을 지우고 메뉴를 만든다. |
| **usage 화면의 탐색 사이드바** | 적용 제외 | Codex 한도 rail은 탐색이 아니라 현재 본문을 보며 함께 참고하는 보조 정보 pane이다. 별도 메뉴나 1항목 탐색 sidebar는 만들지 않는다. |

## 2. 타이포그래피 위계

스택은 `system.css`의 `--font-sans` 하나다:
`-apple-system, BlinkMacSystemFont, "Pretendard Variable", Pretendard,
"Apple SD Gothic Neo", system-ui, sans-serif`.
**웹폰트를 새로 불러오지 않는다** (성능·CSP). 시스템 폰트가 먼저 오고 Pretendard는
비-애플 환경의 한글 폴백이다.

- **디스플레이·타이틀급(`--fs-display*`, `--fs-title-1`)은 30자 이하 헤드라인 전용.**
  서술문(주어+서술어를 갖춘 완결 문장)과 두 개 이상의 문장은 본문 크기(`--fs-body*`)로
  조판한다. "타이틀 폰트에 단락 양"이 이 헌장이 막는 제1 결함이다.
  단, 애플식으로 **짧은 구를 마침표로 끊는 헤드라인**(예: "기록은 계정에.")은
  전체가 30자 이하이고 구가 둘 이하일 때 허용한다 — 마침표의 유무가 아니라
  **글의 양**이 판정 기준이다.
- 글 양과 글자 크기는 반비례한다. 강조하고 싶은 긴 문장은 크기가 아니라
  배치(여백, 구분선, 배경면)로 강조한다.
- **자간**: 디스플레이·타이틀은 음수 자간(`--ls-display` / `--ls-title`), 본문은 0.
  본문에 음수 자간을 주지 않는다 — 한글에서 획이 붙는다.
- **한국어 텍스트 컨테이너에 `word-break: keep-all` 필수** (`overflow-wrap: break-word`
  병용). `system.css`가 `body`에 전역으로 건다. 이를 뒤집는 지역 규칙을 쓰지 않는다.
- 억지 줄바꿈(`<br>`, 공백 조절)으로 조판을 교정하지 않는다. 줄바꿈이 어색하면
  크기 배정이 틀린 것이므로 크기를 내리거나 `max-width`(한글은 `em`, `ch` 금지)로 잡는다.

## 3. 색 — 진짜 다크

- **캔버스는 순검정 계열**(`--bg` `#000` ~ `--bg-alt` `#0b0b0d`). 표면은
  `--surface` → `--surface-2` → `--surface-3` → `--surface-4`의 **명도 단차**로 띄운다.
- **강조색은 화면(뷰)당 1색.** 기본 강조는 `--accent` 하나로 수렴시킨다.
  섹션마다, 앱마다 강조색을 바꾸지 않는다.
- 상태색(`--green*`, `--red*`, `--orange*`)은 상태 표시(성공·오답·경고)에만 쓴다.
  장식·구획 목적으로 상태색을 쓰지 않는다.
- **금지: 그라디언트 장식, 유리 효과(blur/backdrop-filter), 무지개·다색 보더,
  카드에 드리우는 드롭섀도.**
- 색 토큰은 `assets/css/system.css`가 **단일 원본**이다. 다른 파일에서 커스텀 프로퍼티를
  *정의*하지 않는다(유일한 예외: `smstudy` 인쇄 팔레트, `@media print` 안 `html` 셀렉터).

### 3.1 대비 — 전수 검산 의무 (승격된 규칙)

색 토큰을 신설·변경하면 **그 토큰이 얹히는 모든 배경 조합의 대비를 실제로 계산하고,
계산값을 토큰 정의 옆 주석에 남긴다.** 하나만 확인하고 나머지를 유추하지 않는다.
알파 합성 배경(예: `-soft` 뱃지 배경)은 부모 표면별로 따로 계산한다.

- 본문 텍스트 **4.5:1** 이상, 큰 글자(≥24px 또는 ≥19px bold) **3:1** 이상.
- 용도 제약 주석("비활성 전용" 등)이 붙은 토큰은 그 제약 밖에서 쓰지 않는다.
- `system.css` 상단의 대비표와 실제 토큰 값이 어긋난 채로 두지 않는다.

## 4. 깊이 — 명도 단차 + 1px 헤어라인

깊이는 **표면 명도의 한 단 차이**와 **1px 헤어라인**으로만 만든다. 애플 시스템 UI의 방식이다.

- 카드·리스트·툴바·패널에 `box-shadow`를 쓰지 않는다.
- `--shadow-*` 토큰은 **떠 있는 오버레이 전용**이다: 시트(모달), 토스트,
  세그먼티드 컨트롤의 선택 인디케이터. 그 외 사용은 리뷰에서 major다.
- 보더는 `--line-faint`(면 구획) → `--line`(요소 경계) → `--line-strong`(강조 경계)
  순으로 올린다. 한 화면에서 세 굵기를 모두 쓰지 않는다.
- 표면을 두 단 이상 건너뛰지 않는다(`--bg` 위에 바로 `--surface-3`을 얹지 않는다).

## 5. 이모지 체계 (사용자 명시 선호)

이모지는 **장식이 아니라 식별자·구획 표지**다. 체계 안에서 쓰면 화면이 읽히고,
체계 없이 뿌리면 슬롭이 된다.

- **같은 대상엔 언제나 같은 이모지.** 단원·섹션·상태·앱마다 이모지 1개를 고정하고,
  그 매핑은 **화면마다 단일 원본**(데이터 파일 또는 JS 상수 객체) 한 곳에서만 정의한다.
  마크업에 직접 이모지 리터럴을 흩뿌리지 않는다 — 자동 검사가 매핑을 원본에서 도출한다.
- **한 행(row)에 이모지 1개.** 제목과 부제에 각각 붙이지 않는다.
- 문장 *안*에 이모지를 넣지 않는다. 행의 선두(리드) 또는 배지 안에만 둔다.
- **광학 크기와 정렬은 전용 클래스로 고정한다** — `.emoji`(인라인 리드),
  `.emoji-box`(고정 정사각 컨테이너), `.emoji-lg`(섹션 헤더). 이모지 폰트는 서체마다
  기준선이 달라 `font-size`만으로는 정렬이 흔들린다. 클래스를 우회해 인라인으로
  크기를 주지 않는다.
- 접근성: 의미를 이모지가 단독으로 지지 않는다. 텍스트 라벨이 항상 함께 있고,
  이모지 요소에는 `aria-hidden="true"`를 붙인다.
- **개수 상한을 두지 않는다.** 대신 *체계* 상한을 둔다 — 한 화면의 이모지는 모두
  하나의 매핑에서 나와야 하고, 매핑에 없는 즉흥 이모지는 금지다.

### 5.1 사이트 공통 이모지 (3a에서 고정 — 3b·3c는 이 값을 그대로 쓴다)

| 대상 | 이모지 | 쓰이는 곳 |
|---|---|---|
| WordMaster | 📗 | 드로어·앱 내 헤더 |
| 사회·문화 (smstudy) | 📘 | 드로어·앱 내 헤더 |
| 사용량 (usage) | 📶 | 드로어(소유자 전용 그룹) |

admin 사이드바 항목은 v5에서 이모지 슬롯을 걷어내고 텍스트 행으로 바꿨다(§8 로고
엠블럼이 최상단에 대신 들어간다). 그 매핑(adminOverview·adminUsers·adminSessions·
adminAnswers)은 `site-emoji.js`에서 함께 지웠다 — 아무도 읽지 않는 매핑을 남기지 않는다.

랜딩 본문에서 학습 콘텐츠를 걷어내면서(§1) 동기화 리스트가 사라졌고, 그 리스트만
쓰던 💾·🔁·📱는 매핑에서 함께 지웠다. 아무도 읽지 않는 매핑을 남기지 않는다.

앱 안의 단원·상태 이모지는 3b·3c가 각 앱의 데이터 파일에서 정의한다. 위 3개와
겹치는 이모지를 다른 대상에 쓰면 게이트가 실패한다.

### 5.2 게이트

`scripts/validate.mjs`의 `validateEmojiSystem()`이 다음을 강제한다. 검사 대상 이모지
목록은 유니코드 속성으로 **소스에서 자동 도출**한다(LESSONS 규칙 5).

1. 마크업 안의 모든 그림문자는 `.emoji` / `.emoji-box` / `.emoji-lg` 슬롯 **직속**이어야 한다.
   JS 렌더러도 같다 — 다만 데이터 위치의 이모지(매핑 원본)는 허용한다.
2. 한 슬롯에 이모지 하나, 한 `.list-row`에 이모지 하나.
3. 대상↔이모지는 사이트 전체에서 일대일이다(같은 대상엔 같은 이모지, 한 이모지는 한 대상).
   대상 라벨은 `.list-row-title` / `.title-1~3` / `.sidebar-item` / `.list-group-head`에서 도출한다.

이 검사가 **못 보는 것**: 이모지의 의미 적절성, 이미지·SVG 안의 그림 문자,
런타임 조립 문자열. 적절성은 사람이 §11 체크리스트에서 본다.

## 6. 밀도 — "미감과 컴팩트함을 동시에"

- **문장 하나에 카드 하나를 두르지 않는다.** 항목 나열은 카드 스택이 아니라
  **그룹 리스트 행**(`.list-group` / `.list-row`)으로 합친다.
- 세로 리듬을 줄인다. 한 화면에서 스크롤 없이 보이는 정보량을 늘리는 것이 목표다.
- 서술문을 **명제**로 줄인다. 문장이 아니라 판정 기준을 적는다.
- 카드(`.card`)는 정보의 **경계가 필요할 때만** 쓴다. **카드 3연속 스택이 나오면
  설계를 의심하라** — 대개 그룹 리스트, 표, 또는 구분선으로 충분하다.
- 장식 프리미티브(번호 뱃지 / 프로그레스 바 / 통계 타일 / 색 배너)는 한 뷰에 **2종 이하**.
  프로그레스 바는 **실제 진행 데이터**에만 쓴다(정적 콘텐츠 비중 표현 금지).

## 7. 컴포넌트 프리미티브 (`system.css` 단일 원본)

모든 화면은 아래 클래스를 **소비**한다. 화면 전용 CSS에서 같은 모양을 다시 만들지 않는다.
새 프리미티브가 필요하면 `system.css`에 추가하고 이 표를 함께 갱신한다.

### 7.1 그룹 리스트 — 학습·설정 화면의 기본 골격

| 클래스 | 용법 |
|---|---|
| `.list-group` | 둥근 컨테이너(`--surface` + `--line-faint` 헤어라인). 행을 감싼다. |
| `.list-group-head` | 그룹 위의 대문자 라벨(iOS 섹션 헤더). `.list-group` **바깥** 형제. |
| `.list-group-foot` | 그룹 아래의 캡션 각주. `.list-group` 바깥 형제. |
| `.list-row` | 행. `<a>`/`<button>`/`<div>` 어디에나. 최소 높이 44px(터치 타깃). |
| `.list-row-lead` | 행 선두의 이모지/글리프 슬롯. 안에 `.emoji-box`를 둔다. |
| `.list-row-body` | 제목+부제 묶음. 남는 폭을 전부 먹고 `min-width: 0`으로 축소 안전. |
| `.list-row-title` | 행 제목(본문 크기, `--text`). |
| `.list-row-sub` | 행 부제(작은 본문, `--text-2`). 한 줄 권장. |
| `.list-row-value` | 행 우측 값(수치·상태). `--text-2`, tabular-nums. |
| `.list-row-nav` | 우측 chevron(`›`)을 붙인다. 이동하는 행에만. |
| `.list-group.is-inset` | 카드 안에 들어가는 그룹(배경을 `--surface-2`로 한 단 올림). |
| `.list-group-head-row` | **헤더 + 우측 버튼 한 줄** 변형. `.list-group-head`를 안에 넣고 오른쪽에 `.btn-sm`을 둔다. 이 줄이 헤더의 좌우·아래 여백을 통째로 갖는다 — 부모에 `gap`을 또 주면 리듬이 두 배가 된다. |
| `.list-row-stretch` | 행 전체를 진입점으로 늘리는 버튼/링크. 행 안에 **체크박스·스위치가 함께 있을 때 필수**다(컨트롤을 버튼 안에 중첩하면 마크업이 무효). `::after` 오버레이가 행을 덮고, hover는 행 전체가 받는다. |
| `.list-row-accessory` | 오버레이 위로 올라오는 행 우측 컨트롤(체크박스·스위치). `.list-row-stretch`와 짝이다. |
| `.list-row:disabled` / `[aria-disabled="true"]` | 비활성 행. `opacity: .45` + hover 배경 무효화. |

행 사이 구분선은 `.list-row + .list-row`에 **인셋 헤어라인**으로 자동 생성된다.
직접 `border-top`을 그리지 않는다.

### 7.2 접힘 그룹 (disclosure)

`<details>` / `<summary>` 위에 얹는다. 그룹 리스트와 같은 곡률·헤어라인이고,
summary 행의 기하는 `.list-row`와 같은 토큰(`--row-min-h` / `--row-pad-*`)을 쓴다.

| 클래스 | 용법 |
|---|---|
| `.disclosure` | `<details>`. 둥근 컨테이너 + `overflow: hidden`. |
| `.disclosure-head` | `<summary>`. 기본 마커를 지우고 우측에 회전하는 chevron을 붙인다. |
| `.disclosure-title` | summary 제목(본문 크기, semibold). |
| `.disclosure-hint` | summary 우측 짧은 힌트(개수·상태). chevron 앞에 온다. |
| `.disclosure-body` | 펼침 본문. 위쪽 헤어라인으로 summary와 나뉜다. |

인쇄·자동 측정 주의: 닫힌 `<details>`의 본문은 렌더 트리에 없다. 기하 측정은 그 하위
트리를 제외하고, 인쇄 경로는 `beforeprint`에서 실제로 펼친 뒤 출력한다.

## 8. 로고 (v4에서 확정)

공식 마크는 `assets/logo.svg` **하나뿐이다** — 기하 H 심볼: 세로 바 2개(36×140) 사이에
크로스바가 **떠 있는 정사각형**(36×36, 사이트의 사각 시그니처 ■)으로 들어간 형태,
viewBox `0 0 200 200`. 사용자가 2026-08-27 확정했다. 워드마크·텍스트 나열형 로고는
같은 자리에서 기각됐다 — 글자를 늘어놓는 변형을 다시 만들지 않는다.

- **단일 원본** — 로고가 필요한 곳은 이 파일을 `<img>`로 참조하거나 마크업에 인라인한다.
  인라인할 때도 사각형 3개의 좌표·비율을 바꾸지 않는다. 다른 도형·서체로 로고를
  다시 그리지 않는다 (LESSONS "파생 가능한 것을 손으로 적지 않는다"와 같은 원리).
- **색은 `currentColor`** — 파일의 fill이 `currentColor`이므로 얹히는 자리의 CSS
  `color`가 곧 로고 색이다. 다크 캔버스(§3) 위에서는 `--text` 계열 흰색, 인쇄·밝은
  배경에서는 검정. 로고에 강조색·그라디언트·그림자를 입히지 않는다(§3·§4 금지와 동일).
- **여백** — viewBox에 사방 30/200(15%) 안전 여백이 이미 포함돼 있다. 추가 패딩을
  계산해 두르지 않는다.
- **파생물**(파비콘·og 이미지·앱 아이콘)은 이 SVG에서만 만든다. 파생 시 배경을 깔면
  순검정 위 흰 마크 또는 순백 위 검정 마크, 두 조합만 쓴다.

**주의(3b·3c 계약)**
- `.list-row`의 구분선은 `+` 결합자로 그려진다. 행 사이에 다른 요소를 끼우면 선이 끊긴다.
  필요하면 그룹을 나눠라.
- `.list-row-body`에는 `min-width: 0`이 이미 걸려 있다. 자식에서 `white-space: nowrap`을
  쓰면 가로 넘침이 난다.
- 그룹 안 텍스트에 `--text-3`을 쓰지 마라 — `--surface-3` 위 3.85:1로 캡션 하한 미달이다
  (`system.css` 대비표 참조).

## 8. 카피 (문구)

- 화면에 넣는 문장은 짧게. 본문 한 문장 60자 이하, 헤드라인 30자 이하.
- 학습 화면에 마케팅 어법("~해보세요", "강력한", "완벽한")을 쓰지 않는다.
- **구현 완료 전 오타·어색한 줄바꿈 교정 패스를 1회 수행**하고, 리뷰는 화면의
  실제 렌더 텍스트를 읽으며 교정 여부를 확인한다.

## 9. 다이어그램

CSS 조판(그리드·플렉스)으로 만든다. **손계산 SVG 좌표 금지** — 겹침이 원리적으로
불가능한 조판을 쓴다(사이클3 결론).

## 10. 검증 — 수치가 못 재는 것

- 기계 게이트(대비·토큰·변경량·a11y)는 "틀리지 않음"만 보증한다.
- **시각 품질은 눈으로 확인한다**: 구현자와 리뷰어는 완성 화면을 레퍼런스(§1)와
  나란히 놓고 대조한다. computed style 수치 확인은 보조 수단이지 대체 수단이 아니다.
- 스크린샷 확보가 환경상 불가능하면 그 사실을 산출물에 명시하고, DOM 기하 측정
  (겹침·이탈·넘침)으로 대체했음을 완료 보고에 포함한다 (조용히 생략 금지).
- **측정 전 대상 요소가 실제로 보이는 상태인지 확인한다.** `display:none`인 요소를
  재고 "겹침 0"이라 보고한 전례가 있다.

## 11. 리뷰 체크리스트

- [ ] 화면별 레퍼런스가 plan에 명시됐고 결과물이 그 어법 안에 있는가 (§1)
- [ ] 운영 화면이 한 번에 한 뷰만 내는가, 사이드바가 그룹 라벨로 묶였는가, 요약 스트립이
      라벨/값 위계를 지키는가 (§1.1)
- [ ] 디스플레이급 크기에 문장·단락이 조판된 곳이 없는가 (§2)
- [ ] `keep-all` 누락·어절 쪼개짐·억지 줄바꿈이 없는가 (§2)
- [ ] 한 뷰의 강조색이 1색으로 수렴하는가, 상태색이 장식으로 쓰이지 않았는가 (§3)
- [ ] 새 토큰의 대비가 **모든 배경 조합**에 대해 계산되어 주석에 있는가 (§3.1)
- [ ] 카드·리스트에 `box-shadow`가 없는가, 깊이가 명도 단차+헤어라인인가 (§4)
- [ ] 이모지가 단일 매핑에서 나오는가, 한 행에 1개인가, 전용 클래스를 쓰는가 (§5)
- [ ] 문장 하나짜리 카드·카드 3연속 스택이 없는가, 장식 2종 이하인가 (§6)
- [ ] 화면 전용 CSS가 `system.css` 프리미티브를 다시 구현하지 않았는가 (§7)
- [ ] 오타·마케팅 어법이 렌더 화면에 없는가 (§8)
- [ ] 시각 대조를 실제로 수행했는가 (미수행 시 보고에 명시됐는가) (§10)
